# Project Rules For Codex

- Use only the Python standard library and SQLite through `sqlite3`.
- Do not call external APIs, add telemetry/CDN resources, or add Docker/database-server components. The existing optional local Web UI is allowed; keep it local-only.
- Treat original OpenAI/ChatGPT export ZIP files as read-only. Never delete, move, overwrite, or modify them. The CLI accepts `--delete-input-on-success` only as a fail-closed compatibility option: the current supported Python/OS contracts cannot exclude a pre-open non-cooperating writer between final verification and unlink, so production refuses before staging or renaming. Web uploads may delete only the server-side temporary copy.
- Do not print real exported conversation titles, messages, JSON snippets, HTML, image names, or attachment contents to the terminal.
- Test behavior first with synthetic fixtures. Do not copy real chat content into fixtures.
- Before importing a real export, run `inspect` and review shard counts and warnings.
- Support sharded `conversations-*.json` natively. Do not merge shards into one large JSON file.
- If default input discovery sees only unambiguous `conversations-000.json`, `conversations-001.json`, etc. shards and no ZIP, treat the current directory as the input source. Keep multiple ZIPs, mixed `conversations.json` plus shards, or otherwise ambiguous JSON selections explicit errors.
- Use file-level strictness and element-level tolerance: a conversations file must have a list top level, but bad elements inside the list are warnings, not fatal errors.
- Archive all mapping nodes in SQLite. Export only the current UI path by default.
- Default Markdown/TXT/manifest exports must be deterministic: do not include current time, run IDs, absolute output paths, random values, or temporary paths in exported file contents.
- Export writes must compare final bytes first and avoid rewriting unchanged files. Use atomic replacement for changed files.
- Import warnings are per import run. Reimporting the same ZIP may add warning rows for the new run without duplicating conversations or nodes.
- Incremental import must be non-destructive by default: unchanged conversations stay unchanged, changed conversations replace their own nodes/FTS rows, new conversations are inserted, and conversations missing from a newer ZIP are retained unless a future explicit prune/mirror feature is requested.
- Post-commit summary updates (timing fields added after the main commit succeeds) and connection close are best-effort. If they fail, the import is still successful — `import_runs.status` stays `finished` and the command exits 0. Structured warnings (`summary_update_after_commit_failed`, `import_connection_close_failed`, `summary_update_after_close_failed`) are emitted but the import is not rolled back or marked failed.
- Default export updates current manifest files and skips unchanged files, but does not prune historical leftover files from an output directory.
- Web UI work must stay local-first: bind to `127.0.0.1` by default, do not add analytics, telemetry, CDN scripts, remote fonts, remote images, or external API calls.
- The Web UI may start without an existing DB and may import a user-selected ZIP through local multipart upload. The uploaded copy is temporary; never delete the user's original ZIP unless the explicit CLI `--delete-input-on-success` option was used.
- Web import jobs must use the shared import pipeline, run at most one writer job per process, and automatically verify/stats/web-index after success.
- Frontend import diagnostics render every structured `cleanup_warnings` item for preflight and terminal jobs with localized safe code/path-kind labels, retain the deprecated scalar fallback, deduplicate by job snapshot, and never expose paths, filenames, OS messages, or error classes.
- Optional Web FTS5 trigram indexes (`web_message_trigram`, `web_title_trigram`) include automatic shadow-table cleanup on drop and recreate. `web-index` must be able to recover from corrupted FTS5 indexes by dropping all known shadow tables and recreating the index from scratch.
- Optional Web index rebuilds process canonical and trigram rows in bounded keyset batches with explicit byte budgets, resolve each message once, and expose stage plus processed/total progress. Oversized rows remain searchable through a recorded canonical-verifier fallback. Publication stays atomic in one transaction: the previous current index remains readable until commit, and internal/CLI/Web import-job cancellation or any build/metadata/SQLite failure rolls back every replacement object. The Web cancel endpoint applies only to a running import job's index stage, exposes requested/cancelled state, and is not an independent build job. Document the full-build `BEGIN IMMEDIATE`, single-writer, and temporary-disk cost.
- `verify` reports `optional_web_index_error` and a recovery hint when `PRAGMA integrity_check` fails only on optional Web search indexes. Core conversation data is not falsely reported as corrupt in this case.
- CLI verify and Web health derive `message_fts_rebuildable` from the same bounded runtime FTS5 probe. Missing, capability-unavailable, and damaged states remain distinct; unrelated SQLite runtime errors propagate through structured classification.
- Project logs use Python `logging` levels debug/info/warning/error/none. Logs must not include chat titles, message text, snippets, raw JSON, or parser warning payloads.
- Ordinary Web list/message APIs must not expose `raw_message_json`, `raw_json`, or full parser warning payloads. They may return normalized message text and bounded `raw_preview` for the selected local browser view. The per-message raw endpoint provides only a bounded/capped larger raw preview; truncated responses must prefer plain `raw_text`, and the UI must present only that capped preview.
- Search code must parameterize SQL and build FTS `MATCH` expressions through a query builder; never concatenate raw user input into SQL.
- Global `path=current` search must derive path-independent conversation candidates first and materialize effective-current only for that candidate scope; exclusion-only searches may use the explicit full-database fallback. Reader hit navigation loads one initial page and appends lazily near the loaded boundary.
- Keep SQLite search/index resolver evaluation to once per candidate row without requiring `AS MATERIALIZED`; use the portable non-flattening query shape and retain resolver-count regressions.
- Frontend code must render chat text as text nodes, not unsanitized HTML.
- Web list and message APIs must remain paginated. Do not add endpoints that load every conversation or every node into the browser.
- Web search must preserve exact substring fallback for Chinese, code symbols, file names, command flags, and quoted phrases even when FTS tokenization fails.
- `path=current` search must match reader fallback semantics per conversation: when a conversation has current-path nodes, restrict to that current path; when a damaged/incomplete conversation has no current-path nodes at all, search the same all-node fallback that the reader displays. Do not turn all `path=current` searches into global `path=all`.
- Preserve the distinction between raw node membership and effective reader visibility. `is_on_current_path` remains the raw node flag; fallback conversations with zero current-path nodes need explicit metadata such as `current_path_fallback_to_all`, `effective_path`, or `effective_visible_in_current_view` so the UI does not mark fallback-visible messages as hidden branch hits.
- Reader message APIs default to visible-message pagination when internal nodes are hidden, so root/system/developer/tool/technical/empty prefixes cannot produce an empty first page. Use `include_internal=true` only for internal/debug views, explicit Show internal reader state, and export/copy paths that need the complete node set before applying their own visibility contract.
- Reader `around_node_id` offsets must be computed against the same pagination collection that the response uses: visible-only rows when `include_internal=false`, the full node collection when `include_internal=true`, and the effective all-node collection for damaged current-path fallback conversations.
- Conversation search exclusions are conversation-level: any excluded title or message in the selected scope/path removes that conversation from conversation results. Message search remains hit-level and returns only message hits that do not contain excluded fragments. Keep README, SearchHelp, `/api/schema`, reader highlights, selected metadata, and tests aligned with this contract.
- Normalize role comparisons consistently by treating underscores as slashes. Keep `tool/system` as the public canonical role filter while accepting `tool_system` as an alias; SQL filters, hidden counts, search, and reader highlights must all use the same canonical role semantics.
- Search diagnostics must not present legacy raw `message_fts` as a normalized-safe candidate backend. Report normalized-safe candidates or scan fallbacks (`normalized_trigram`, `normalized_title_trigram`, `normalized_scan`, `normalized_title_scan`, `full_scan`) as `candidate_backend`; report legacy raw FTS/index presence only in separate fields or notes. Title-only contexts such as `scope=title`, `title=...`, and `title:...` must report the title candidate path, not the message path.
- Keep search diagnostics synchronized across backend responses, `/api/schema`, frontend TypeScript types, UI interpretation, i18n, and DOM smoke tests. UI text must use localized user-facing labels and never expose internal enum or field names such as `candidate_backend`, `web_index_missing`, `normalized_trigram`, `normalized_title_trigram`, `normalized_scan`, `normalized_title_scan`, `full_scan`, `actual_fallback_note`, `estimated_backend_note`, or `diagnostics_accuracy`.
- Non-loopback Web upload policy separates remote opt-in from local large defaults. `CHATGPT_ARCHIVE_ALLOW_REMOTE_UPLOADS=true` only allows explicit per-limit env overrides above remote-safe defaults; unset limits remain remote-safe. Full local defaults on a trusted non-loopback network require `CHATGPT_ARCHIVE_REMOTE_UPLOAD_PROFILE=local`. Keep README variants, `/api/schema`, CLI warnings, and tests synchronized when this policy changes, including `CHATGPT_ARCHIVE_MAX_UPLOAD_TOTAL_MEMBERS` and its local/remote defaults.
- `/api/schema` must expose the effective upload constraints for the running host/profile, not only static env documentation. Keep the schema values synchronized with the actual `UploadPolicy` used by `/api/import/upload`.
- Web upload ZIP limits run before import, but direct JSON parsing, SQLite writes, and web-index rebuilds still consume memory, disk, and CPU proportional to decoded JSON size. Document this as a bounded-resource concern without reducing trusted loopback large-archive defaults.
- CLI and Web exports default to the effective current path and visible-only messages; all-path and internal-message export require explicit options and manifests record both choices. CLI node loading must remain conversation-batched rather than N+1. Reader `Copy current path conversation` and Web export use dedicated bounded complete-text streams, respect the current reader path plus the Show internal setting, and must not accumulate reader pages or inherit reader payload truncation. Copying the full current path ignores active search filters, while `Copy visible` copies only already loaded visible messages.
- Export filename parts must stay cross-platform safe, including Windows reserved device basenames (`CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9`, `LPT1`-`LPT9`) and trailing dots/spaces, even when generated on macOS or Linux for use on Windows.
- Windows reserved device basename handling must also cover superscript-digit forms such as `COM¹`, `COM²`, `COM³`, `LPT¹`, `LPT²`, and `LPT³`, including when an extension is present.
- Scanner source discovery must ignore macOS metadata paths (`__MACOSX`, AppleDouble `._*`, and `.DS_Store`) for ZIP and directory inputs before selecting conversation JSON sources. Do not let metadata files create duplicate-source errors or outrank real `conversations.json` / `conversations-*.json` files.
- Directory imports use component-safe POSIX opens where available; the portable path fallback cannot eliminate every untrusted concurrent local replacement race, so documentation directs that threat model to the original read-only ZIP. Crash-left upload directories are not auto-deleted without an ownership-marker/age design; manual cleanup must verify exact prefix, ownership, age, no links, and no active job, never user ZIPs or wildcards.
- Frontend technical-payload folding should prefer backend metadata (`is_internal`, role, `content_type`) and must not fold ordinary user/assistant JSON examples only because they contain tool-like keys such as `search_query` or `ref_id`.
- ZIP inputs must not silently import ambiguous duplicate conversation JSON member names. Detect duplicate `conversations.json` or `conversations-*.json` source paths and reject or otherwise make the selected member deterministic before parsing.
- Imports must invalidate or maintain optional Web search indexes (`web_message_norm`, `web_title_norm`, trigram tables). Never leave stale Web index rows after an incremental import.
- Frontend request handlers must guard against stale async responses with `AbortController`, request IDs, or equivalent logic.
- Web UI preferences are local-only `localStorage` state. Keep i18n/settings code lightweight and do not translate archived chat content.
- Keep the left conversation list and right message reader independently scrollable inside a fixed-height app shell; preserve pagination and avoid loading the whole database into the browser.
- DOM/browser tests must use synthetic databases and must not depend on or print real chat content.
- Prefer `npm ci` for frontend dependency installation when `webui/package-lock.json` exists; do not treat `node_modules` as a deliverable.
- Keep all `README*.md` files functionally synchronized when Web install, startup, acceptance commands, diagnostics, raw preview, copy/export, upload policy, upload slot, or release packaging behavior changes. README tests should catch missing structure, command blocks, environment variables, and core feature facts across languages.
- Keep JSON logs under ignored paths such as `logs/`; `*.jsonl` is treated as a local log artifact and must not be included in delivery.
- `compileall`, unit tests, `npm ci`, typecheck, and build may generate Python cache, bytecode, `webui/node_modules`, `webui/tsconfig.tsbuildinfo`, coverage/typecheck caches, and browser test output; run `python tools/clean_generated_artifacts.py --fail-on-blocked` before final delivery clean, while keeping `webui/dist`. The cleaner must not delete user data such as databases, ZIP files, SQLite sidecars, `archive/`, `exports/`, or `logs/`; it reports those as blocked sensitive paths for manual handling. Prefer cross-platform Python cleanup over POSIX-only `find` or `rm` commands in shared docs.
- Release ZIPs must include Python source, tests, docs, `requirements-web.txt`, `AGENTS.md`, frontend source, frontend tests, frontend config/package files, and built `webui/dist` assets. They must exclude `.git`, `archive/`, `exports/`, databases and SQLite sidecars, user ZIP/export JSON files, `webui/node_modules`, Python caches, AppleDouble `._*`, `__MACOSX`, `.DS_Store`, `webui/tsconfig.tsbuildinfo`, logs, `*.jsonl`, and `tools/release.zip`.
- Search examples should work on macOS, Windows, and Linux. Use double quotes for search queries with spaces so PowerShell/cmd users can copy the command directly.
- Validate Host for static UI and every API route. Loopback defaults stay finite; non-loopback binds require explicit `CHATGPT_ARCHIVE_ALLOWED_HOSTS`. Trust forwarded host/proto headers only when the direct peer matches `CHATGPT_ARCHIVE_TRUSTED_PROXIES`; remote writes require a trusted same-origin Origin, while trusted loopback may accept clients without Origin.
- Reject JSON `NaN`/`Infinity` at decode time and normalize string non-finite timestamps to NULL with warnings. Keep legacy databases API-safe and make `verify` report non-finite canonical timestamps.
- Failed imports must persist a structured post-rollback warning and a failed run summary whose warning totals match actual rows. Preserve specific preflight/source-scan/JSON/top-level error codes through CLI and Web jobs; post-commit verify/stats/index failures are not import transaction failures.
- Export filename budgets apply to the complete UTF-8 basename, including extension, date, stable conversation ID, and collision suffix. Release ZIPs must be built in a target-directory temporary file, verified against an all-payload size/SHA-256 manifest, and atomically published without damaging an existing release on failure.
- `internal_hidden_count` is canonical; `technical_hidden_count` is a deprecated identical compatibility alias. Message-search pages always expose `total_exact`; an incomplete bounded scan reports false, while a completed scan may prove true even with `count_total=false`. Around-node pages expose found, visible, effective-membership, and applied metadata.
- Copy URL must explicitly serialize `match_mode`, `layout`, and `show_internal` so recipient local settings cannot change the shared view. This version does not promise browser Back/Forward restoration of step-by-step search history.
- Trusted proxy handling uses a strict single-edge contract. Ignore forwarded headers from untrusted peers; for a trusted direct edge reject repeated Host/Forwarded headers, comma chains, malformed syntax, and conflicts between `Forwarded` and `X-Forwarded-Host/Proto`.
- Failed import summaries must distinguish `attempted_*` work from `committed_*` work. Persist failed runs through a fresh connection and surface secondary persistence failures explicitly.
- Legacy/raw readable text recovery must use one bounded resolver across reader, search, highlight, copy, CLI export, and Web export. Invalid, oversized, and genuinely non-text raw payloads must remain canonical placeholders.
- Effective-current diagnostics distinguish selected-chain and raw-flag topology. Closed raw-flag cycles with no leaf must still report cycle diagnostics, and around metadata must distinguish effective-current membership from requested-path membership.
- Verify effective-current counters use conversation units: selected-chain counters read only selected-chain fields, raw-flag-topology counters read only raw fields, and any retained aggregate is named as an aggregate. Health and verify stream a complete database-wide foreign-key check, retain bounded samples, expose exact/complete metadata, and document that CPU/VM work remains proportional to database size.
- Message-search pages always expose `total_exact`; conversation pages do not promise it. Filter-only and exclude-only queries may filter conversations but do not create message hits or reader highlights without a positive message-text term.
- Import job IDs are lowercase 32-character hex. Pre-job cleanup failure must preserve the primary error while exposing a safe cleanup warning and error type without a temporary path.
- Japanese and Spanish are partial UI translations and must be labelled as such. English, Simplified Chinese, and Traditional Chinese translation dictionaries require compile-time key parity.
- Release building must validate an authoritative required-file list independent of collector output before writing, and missing required leaves must not damage an existing release ZIP.
- The canonical SQLite schema is versioned only with `PRAGMA user_version`; version 3 requires explicit `NOT NULL` identity columns, version 4 adds durable field-scoped address/graph revision domains, and current version 5 adds durable row-local display revisions plus compatibility state. Read-only CLI and Web paths never run migration DDL. Migration decisions, rebuilds, validation, and version publication occur under the same write-lock transaction; migration performs a conservative disk preflight before taking the write lock, reports content-free progress, supports cooperative cancellation, and rolls back on cancellation, interruption, ENOSPC, or SQLite failure. NULL identities are rejected without guessed repair. Run the explicit `migrate` writer after an external backup, and keep health/API `database_migration_required` gates aligned with the current schema contract.
- Treat `message_fts` and Web normalized/trigram tables as optional, rebuildable capabilities. Only exact missing-module/optional-object errors may downgrade to a fallback; malformed, locked, readonly, I/O, programming, and core-schema failures must propagate with structured diagnostics.
- Default message APIs return one reader-budget-bounded resolved body in `display_text` plus truncation/total-exactness metadata; do not reintroduce duplicate `content_text` or `render_text` aliases. Keep raw parsing bounded and reuse one row-level resolution across preview, visibility, payload, and highlight.
- ZIP total-member limits count every central-directory entry, including directories and metadata. Unexpected upload preflight failures use safe JSON `upload_preflight_failed` responses, and cleanup diagnostics accumulate structured `cleanup_warnings` entries without replacing earlier warnings.
- JSON/source failures keep stable stages and codes: invalid UTF-8 and bounded-integer failures are `json_decode`; safe open/not-regular/read/changed failures are `source_read`. Do not expose OS messages or paths.
- Conversation JSON is streamed one top-level array element at a time for standalone, directory, and ZIP inputs. Each element has both a 32 MiB UTF-8 input limit and a 32 Mi decoded-character limit. Accept at most one leading UTF-8 BOM; reject repeated/interior BOMs, UTF-16/32, mixed, or invalid encoding consistently.
- ZIP64 structures are supported through Python `zipfile` and a small forced-ZIP64 regression fixture. Documentation must distinguish that structural coverage from an unperformed physical >4 GiB acceptance run and retain every configured member/byte/ratio/resource limit.
- New canonical conversation, mapping-node, message, current, parent, and child IDs are limited to 512 characters at import. Skip an element with a content-free warning when any graph ID is over the limit; never truncate IDs. Primary query-based `/api/by-id/*` routes accept bounded legacy IDs up to 16 Ki characters without path ambiguity; legacy path routes remain limited to route-safe new-import IDs.
- Ordinary read gates and default Web health must stay bounded and must not run full `foreign_key_check`; exact database-wide checking belongs to CLI `verify` and `/api/health?deep=true`, with bounded samples and explicit freshness metadata.
- Long display reads use revision-bound opaque cursors and incremental BLOB access. Legacy numeric display offsets are capped at 1,048,576 characters; larger offsets require the cursor. Raw previews use one NUL-safe bounded BLOB query with byte-size/exactness metadata. Visible NUL and isolated surrogates normalize consistently to U+FFFD while raw JSON remains escaped; searchable/indexed text must use the same visible representation.
- Long-display cursor revisions are durable and row-specific in `conversation_nodes.display_revision`: project imports provide a valid revision directly, managed insert triggers repair only absent/invalid external values, and managed update triggers advance only for display-affecting changes. Signed versioned cursors bind database, logical row identity, resolver source, revision, byte offset, and code-point offset; tampering is invalid, while row/source changes are stale. Explicit migration backfills existing rows, and the logical identity binding prevents rowid reuse from reviving stale cursors.
- CLI/Web export must reject before materialization above 100,000 nodes per conversation, 32 MiB per-node canonical/raw input, 128 MiB total conversation input, or 256 MiB streamed output. Effective-current online materialization has the same 100,000-node limit plus a 128 MiB graph-ID input limit. CLI candidates are same-directory temporary files hashed and compared incrementally before atomic replacement. Browser copy aborts before clipboard write above 16 MiB UTF-8 or 8 Mi characters and never writes partial text.
- Long streaming exports retain one consistent SQLite read snapshot until completion, failure, or client disconnect; document that this can delay WAL checkpoints and cause WAL/temp/CPU work proportional to selected data.
- Frontend production builds use a sibling staging directory, validate referenced assets, publish assets first, and atomically replace `dist/index.html` last. An injected-failure self-test must prove the previously published dist remains usable.
- ZIP member read failures keep distinct safe `source_read` codes for encrypted, missing, changed, CRC-failed, and other read failures.
- Upload ingress treats `Origin`, `Content-Length`, and `Sec-Fetch-Site` as single-value security headers. Reject duplicates, non-origin URL components, and non-canonical content lengths before multipart parsing.
- Release ZIP member metadata and ordering are deterministic. Identical payloads must produce byte-identical outer ZIPs while preserving authoritative required-file, internal manifest, hash, delivery, temporary-file, and atomic-replace checks.
- Python Web constraints pin resolved versions but are not a cross-platform hash lock. Document this residual supply-chain risk honestly until a supported Python/OS matrix workflow generates and verifies platform-specific hashes.
- Directory imports use component-wise no-follow opens where supported, but portable fallbacks cannot eliminate every local replacement race. Document the trusted-directory boundary and the read-only ZIP alternative. Crash-left Web upload directories are never deleted automatically; manual cleanup must verify exact prefix, ownership, age, no links, and no active job, and must never target user ZIPs or unchecked wildcards.
- Destructive SQLite DDL for core FTS, optional Web indexes, staging, metadata, generation, and shadow objects requires exact project-ownership validation. Name resemblance is never ownership; preserve colliding user objects and return stable collision diagnostics.
- Optional Web-index builds use unpredictable per-build names plus one durable owner-token lease per database. Contenders fail deterministically, stale recovery revalidates database/build identity and every owned name, and cleanup never drops objects not proven to belong to that lease. Track actual input, normalized, derived, and FTS-bind batch peaks.
- Exact message verification is incremental within independent per-row and request-aggregate budgets. Raw-only fallback has its own tighter byte/character budget. Confirmed hits survive a bounded partial segment; a fixed-size signed server-instance continuation session resumes pending work without embedding conversation or node IDs. Restart, expiry, secret mismatch, cross-worker routing without affinity, generation/index/metadata changes, or database replacement invalidate or stale the token. A response distinguishes exact totals from exact ordering with `total_exact`, `order_exact`, `scan_complete`, and `provisional_order`; when continuation exists, `next_offset` is null. Only non-continuable hard materialization limits return 413. Late-hit navigation uses a row-revision-bound display anchor.
- New imports accept at most 5,000 mapping nodes per conversation element under a joint resource profile: 32 MiB UTF-8 input, 32 MiB decoded characters, 2,500,000 string/primitive tokens, 1,250,000 mapping entries, 1,000,000 array items, depth 256, 1,000 integer digits, 384 MiB estimated decoded heap, and bounded import-batch materialization. Crossing any dimension skips that element with a structured warning while later valid elements continue. The 100,000-node reader/effective-current/export limits exist for compatible legacy or externally written databases and are not import limits.
- `--delete-input-on-success` currently returns `delete_input_secure_identity_unsupported` before journal creation, staging, rename, or canonical import on every supported platform, because descriptor-relative pathname checks and advisory locks cannot prove exclusive ownership against a pre-open non-cooperating writer. The recovery command remains available only for strictly owned journals left by historical supported runs; tokens are bounded and recovery never overwrites a replacement.
- Durable optional Web-index format 6 maps logical conversation/node identities to project-owned stable integer addresses. Canonical implicit rowids are never persisted or exposed across transactions/requests; address-map identity/version and all index format/resolver/normalization/generation metadata participate in currentness and continuation checks.
- Web index/import process locks live in a private per-user registry and contain no database pathname. Existing databases lock both normalized path and file-entity identities so real-path, symlink, hardlink, parent-symlink, and relative aliases contend before lease/staging/write work; new databases bind their entity immediately after creation. Unknown registry objects fail closed and are not changed or removed.
- Web import jobs expose both detailed legacy `outcome` and public `completion_outcome`/`canonical_import_outcome`. Terminal UI and APIs show canonical commit state, committed conversation/node counts, skipped element count, safe warning totals/by-code, cleanup warnings, and optional-index result without exposing exported content or IDs.
- Project bulk imports may aggregate generation advances only inside the same write-lock transaction while exact project-owned triggers are transactionally replaced and restored. Rollback must restore both data and trigger DDL; external writers retain ordinary trigger semantics.
